# Plan 07-01: Content Intelligence Types & Tool Integration

## Goal
Add summarization (INTL-01), sentiment analysis (INTL-04), named entity recognition (INTL-05), and chapterization (INTL-06) as configurable options on the existing transcribe tool, with proper types for both request and response.

## Context
All 4 features are toggle-based options on Gladia's POST /v2/pre-recorded endpoint. They follow the same pattern as existing features (diarization, subtitles): boolean enable + optional config object. The transcribe tool already handles camelCase→snake_case mapping.

## Tasks

### Task 1: Extend TranscriptionConfig in types/gladia.ts
Add request config fields:
```typescript
// In TranscriptionConfig:
summarization?: boolean
summarization_config?: {
  type?: 'general' | 'concise' | 'bullet_points'
}
sentiment_analysis?: boolean
named_entity_recognition?: boolean
chapterization?: boolean
```

### Task 2: Extend TranscriptionStatusResponse in types/gladia.ts
Add response types for intelligence features:
```typescript
// In TranscriptionStatusResponse.result:
summarization?: {
  success: boolean
  is_empty: boolean
  results: string
  exec_time: number
  error: string | null
}
sentiment_analysis?: {
  success: boolean
  is_empty: boolean
  results: Array<{
    text: string
    sentiment: string
    emotion: string
    start: number
    end: number
    channel: number
    speaker: number
  }>
  exec_time: number
  error: string | null
}
named_entity_recognition?: {
  success: boolean
  is_empty: boolean
  results: Array<{
    entity: string
    category: string
    start: number
    end: number
  }>
  exec_time: number
  error: string | null
}
chapterization?: {
  success: boolean
  is_empty: boolean
  results: Array<{
    summary: string
    headline: string
    gist: string
    start: number
    end: number
  }>
  exec_time: number
  error: string | null
}
```

### Task 3: Update transcribe tool input schema and handler
In src/tools/transcribe.ts:
- Add Zod schema fields: `summarization`, `summarizationConfig`, `sentimentAnalysis`, `namedEntityRecognition`, `chapterization`
- Add JSON schema properties in tool definition
- Add camelCase→snake_case mapping in handler config builder

## Verification
- `npm run build` compiles successfully
- Types are consistent between request config and response
- All 4 features can be enabled via transcribe tool inputs
- camelCase→snake_case mapping is correct for all new fields
