    - TranscriptionJobResponse interface with id, result_url fields
    - TranscriptionStatusResponse interface with status ('queued' | 'processing' | 'done' | 'error'), result fields including transcription.utterances
    
    Extend GladiaClient in src/lib/gladia.ts with three methods:
    - startTranscription(audioUrl: string, config: TranscriptionConfig): POST to /v2/pre-recorded with body containing audio_url and spread config
    - getTranscriptionStatus(jobId: string): GET to /v2/pre-recorded/{jobId}
    - transcribeAndWait(audioUrl: string, config: TranscriptionConfig): Combines startTranscription + polling loop:
      1. Call startTranscription to get job ID and result_url
      2. Poll getTranscriptionStatus with exponential backoff (initial: 3s, multiplier: 1.5, max interval: 15s, max total time: 300s / 5 minutes)
      3. Return completed result when status is 'done'
      4. Throw descriptive error if status is 'error' or timeout reached
      5. Use setTimeout-based delay between polls (not blocking)
    
    Polling implementation:
    - Use a simple async sleep helper: const sleep = (ms: number) => new Promise(resolve => setTimeout(resolve, ms))
    - Loop: check status, if 'done' return result, if 'error' throw, otherwise sleep and retry with increased interval
    - On timeout: return partial response with job ID so user can check manually via get_transcription_status
    
    Use same error handling pattern as uploadFile method. Follow research recommendations for API structure.
  </action>
